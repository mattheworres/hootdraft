# HootDraft: PHP Rewrite

Given that HootDraft's underlying dependencies have been outdated for some time, combined with the fact that software vulnerabilities are being discovered and patched at a rate we have never seen thanks to LLMs - I've decided it's time to try and tackle the bitrot that has naturally set in here.

## Overarching Issues

A rudimentary look over the API code, while not revealing perfection, did reveal that most of the issues aren't necessarily in the code (though I will fix those). The issue is that packages/frameworks like Silex have been deprecated and untouched for many years now.

All 241 tests pass on the three servers. Details: `docs/perf/README.md`, `docs/adr/0001` and `0002`.)*

## Known Compromises

Things decided or sidestepped during steps 2 to 4 and the `phprewrite-review` tickets (`.scratch/phprewrite-review/issues/`). Revisit as noted. "The old code" means the `develop` branch. A *Client:* note says whether the AngularJS client depends on the behavior.

- **Native PDO instead of DBAL for queries.** `doctrine/dbal` 4 removed fetch-into-class, `Statement::fetch()` and `setFetchMode()`, which the ~100 prepared statements in the old repositories rely on. The `PDO` service hands them DBAL's own native connection, so the repositories can be ported mostly as-is. **Decided in 4.7: stay on native PDO.** The ~100 prepared statements and `FETCH_CLASS` hydration into the untyped entities work, are covered by the test suite, and DBAL has no equivalent hydration, so a move would be a large diff with no user-visible gain. The three `fetchColumn()` calls are `PDOStatement::fetchColumn()` (not deprecated; only DBAL's own `Statement`/`Connection` lost it) and DBAL already sets `PDO::ERRMODE_EXCEPTION` on the shared handle, so neither needs changing. The one `exec` was removed in 4.5. If this is revisited (for example during the `DraftStatsRepository` tidy), use DBAL directly with a small `Hydrator::into()` helper, not the ORM, one repository at a time.
- **Authentication is a server-side session cookie (step 3).** `hootdraft_session`: HttpOnly, SameSite=Lax, Secure when the request is HTTPS (`cookie_secure: auto`, so behind a TLS-terminating proxy set `framework.trusted_proxies`), valid for a day, stored in `var/sessions` (shared across Deployer releases). `AUTH_KEY`, `AUTH_SECONDS` and `AUTH_KEY_HEADER` are gone with the JWT; everyone is logged out at cutover. Existing users keep their passwords: hashes from the old app verify through Symfony's built-in sha512 x5000 hasher and are rehashed to the modern algorithm (bcrypt/argon, whatever `auto` picks) on that user's next login. Rows still on the old hash are only fully retired once every active user has logged in once. *Client:* depends on it; step 3 removed the token handling, and the browser sends the cookie.
- **New API surface and a client contract:** `POST /logout` and `GET /me` are new. `/me` returns `name`, `is_admin` and `roles` (every granted role with the `security.yaml` hierarchy applied, so an Admin also reports `ROLE_COMMISH`), or 401 (ticket 07). The login, Email Verification and Reset responses do not include `roles`. Every non-GET request must send `X-Requested-With: XMLHttpRequest` (the AngularJS client sets it globally in `requestedWithHeader.config.js`), otherwise 403. The login response no longer contains `token` or `auth_timeout`; the client revalidates its stored login with `/me` at startup and relies on 401s afterwards. *Client:* depends on it; it sends `X-Requested-With`, calls `/me` at start-up and `/logout`. It does not read `roles` from `/me` yet (`cacheRoles` has no caller).
- **Auth behavior changes:** the maximum password length is 72 bytes (was 255; bcrypt ignores the rest, so longer ones are rejected at registration/reset). A Reset never enables an account or makes it Email Verified: `/lostPassword` and `/resetPassword` refuse Email Unverified and Disabled accounts (see "Email Verified is separate from Enabled" below). The reCAPTCHA check is skipped only when `RECAPTCHA_SECRET` is empty **and** `APP_DEBUG=1`, replacing the old "skip for 127.0.0.1" hack, which never worked behind Docker. With an empty secret and `APP_DEBUG=0`, every check fails with `recaptcha-failed` and logs a critical message. Login failures return one generic message for unknown email, wrong password and a Disabled account. A malformed `/login` (not JSON, or a missing, empty or non-string `_email` / `_password`) gets the same message. The one exception is an Email Unverified account with the right password (see below). *Client:* the login, register and reset forms show the `errors` list; they do not depend on these rules.
- **Authentication code layout.** `LoginUserRepository`, `LoginUserService` and `LoginUserValidator` in `src/Domain` started as just what login/register/verify/reset needed; the profile, invite, admin user management, public commissioner lookups and `DeleteUser` were added with their controllers in step 4. `CurrentUser` (`src/Security`) replaces `GetCurrentUser()` / `GetUserFromHeaderToken()`. The email templates live in `templates/email/`. Logging in no longer erases a pending Email Verification Key or Reset Key (the old `Login` called `EraseVerificationKey`): a login with the old password must not cancel a Reset the owner asked for, and keys expire on their own.
- **Email Verified is separate from Enabled.** (Spec: `.scratch/email-verified-split/spec.md`.) `users.emailVerified` is set by the user when they follow the emailed link; `users.enabled` is set only by an Admin (`LoginUserRepository::UpdateAsAdmin`; `Update` never writes it). The Email Verification Key and the Reset Key have their own column pairs (`emailVerificationKey`/`emailVerificationKeyCreated`, `resetKey`/`resetKeyCreated`). Login checks the password first, in `UserChecker::checkPostAuth`. A Disabled user gets the generic failure, even when also Email Unverified. An Email Unverified user gets "Your account email is still unverified. ..." and, when their Email Verification Key is older than 48 hours or missing, a new key and email (no other rate limit: `symfony/rate-limiter` is not installed; the correct password and the expired key limit the volume). Following the emailed link makes the user Email Verified but never lifts a disable, and a Disabled user gets no session from it. `UserProvider::refreshUser` drops the session of a user who is no longer Enabled or Email Verified, which is how an email change ends the session. `/lostPassword` and `/resetPassword` refuse Email Unverified and Disabled accounts. The endpoints are `POST /emailVerification` (was `/verify`, field `_emailVerificationKey`) and `GET /checkResetKey` (was `/verifyToken`, field `_resetKey`); `/resetPassword` also takes `_resetKey`. The client must change its API paths with this release (ticket 03). The emailed link still points at the client route `/verify/:email/:key`; it changes with the client route (ticket 03). This replaces the "a Reset enables an Email Unverified account" idea of `phprewrite-review` ticket 05 (`wontfix`).
- **Client changes beyond step 3c's "smallest changes".** These are AngularJS fixes made during the port and the review, and the Playwright suite sees them:
  - `draft.service.js`: each `getDraft()` call that has to wait for the API gets its own deferred, kept in `pendingDefers`. The API call resolves (or rejects) all of them when it ends. The old code shared one `this.defer` and checked again every 1.5 seconds, five times, so components that mounted together could miss the draft or get a false "unable to load" warning. Draft id comparisons use `idHelperService.isSame` (ticket 03).
  - Register and lost password: after a failed submit, the form clears its captcha value and reloads the reCAPTCHA widget, because the server checks the captcha first and a used token is not valid again.
  - `sessionCheckedResolve` (ticket 08): the home routes and the logged-out-only screens wait for the start-up `/me` check, so a new tab with a valid session shows the logged-in state at once.
  - `errorService.parseValidationErrorsFromResponse` (ticket 14) reads both the `{data, status}` wrapper and a plain `$resource` failure, so Draft edit, Draft create, trades, picks and timers show the server's 400 messages, not "Whoops… (undefined)".
  - The client compares integer JSON values as numbers (ticket 03), and the pro player admin screen says League (ticket 09).
- **Not verified in step 3:** the AngularJS client against the new API in a browser (only linted), real SMTP delivery, the real reCAPTCHA call, and Secure-cookie behavior over HTTPS. There is no login throttling yet (`symfony/rate-limiter` is not installed); add it before this faces the internet.
- **Error handler behavior change:** HTTP exceptions keep their status (404, 403, ...) instead of everything becoming 500, and unexpected errors only reveal their message when `APP_DEBUG=1`. The old handler returned the raw exception message with a 500 always. *Client:* does not depend on the status; it reads `error` or `errors` for the message.
- **A malformed JSON body is a 400.** `JsonRequestListener` answers 400 `{"error": "Request body is not valid JSON."}` for a body with `Content-Type: application/json` that does not decode, and `{"error": "Request body must be a JSON object."}` for a JSON value that is not an object or list. An empty body is still allowed. The old code treated a bad body as an empty one and carried on. `/login` is the exception: it gets the normal login failure (see "Auth behavior changes"). *Client:* does not depend on it (it always sends valid JSON objects).
- **Integer columns are JSON numbers.** On PHP 8.1+, `pdo_mysql` returns integer columns as PHP ints, so the JSON has `"draft_id": 5`, `"enabled": 1`, where the old app sent strings (`"5"`, `"1"`). Decimal and text columns, and values bound by reference (for example `was_drafted` on a created trade asset), can still be strings. Decision: fix the client, not the server. *Client:* depended on strings; ticket 03 changed every `=== '1'` comparison and every id comparison with `$routeParams` (`idHelperService.isSame`).
- **One transaction helper (tickets 11 and 12).** `TransactionService::Run` runs a callable in a transaction, joins a transaction that is already open, rolls back on any `\Throwable` (also PHP `\Error`s such as `TypeError`) and flushes the pending Draft cache resets after the commit or rollback. Every transactional save uses it; no other `beginTransaction` / `rollBack` code is left. The old code caught only `\Exception` (where it had transactions at all), so an `\Error` left the transaction open. The helper rethrows the `\Error` after the rollback, and the services catch only `\Exception`, so the client still gets a 500; only the open transaction is fixed. *Client:* does not depend on it.
- **Symfony project root is the repo root** (`config/`, `src/`, `var/`, `bin/` beside the Angular app); only `api/index.php` is a web entry point, and the web server whitelists what is reachable.
- **Settings moved from `appsettings.php` to `.env` / `.env.local`.** `appsettings.php` is deleted (and no longer git-ignored; the nginx allow list never serves it, so a stale copy on an old server stays hidden). The local `phinx.yml` and `deploy.php` are still ignored by git and untouched; regenerate them with `dep setup` (or copy `deploy/deploy.php.release`) for the new formats. `deploy.php` must be rewritten for Deployer 8 (`host()->set('remote_user', ...)`, no `stage()`, no password option).
- **Phinx is now a runtime dependency** (needed on the server to migrate) and the bundled `deploy/composer.phar` and `deploy/phinx.phar` (2019-era) were removed; the server must have `composer` and PHP 8.5.12+.
- **Vagrant was removed** (Ubuntu 18.04 / PHP 7.2) in favor of the Docker box.

What was run: the Docker nginx config, the Symfony kernel, tests, Phinx migrations, and `nginx -t` on `EXAMPLE_nginx` with a self-signed certificate (its location blocks match the Docker nginx config). The Apache `.htaccess` and IIS `web.config` are removed: only nginx is supported. `dep list` and the `deploy` task tree load correctly.

  - *A saved pick is never reported as failed (ticket 15).* After the commit, add-pick always answers success with `pick` and `next_pick`. `last_5_picks` and `next_5_picks` start as `[]`; if loading them fails, the failure is logged and they stay `[]`. The old code answered "Unable to add pick" (with the raw SQL error) for a pick that was already saved. *Client:* reads `last_5_picks` and `next_5_picks` and shows an empty list when they are `[]`.
  - *New validation.* A trade must have at least one asset ("A trade must include at least one asset.") and two different managers ("A trade must be between two different managers."). Updating a pick that has no `pick_time` (not selected yet) is refused with "Pick #N has not been made yet." (`PickValidator::IsPickValidForUpdate`; `pick_time` comes from the database, not from the request). The old code accepted all three. *Client:* does not depend on them: the trade screen needs one asset and two managers before it sends, and the edit screen lists only Selected Picks. It shows the server message if one is refused.
  - *Fixed rather than kept:* `ProPlayerRepository::SaveProPlayers` built `DELETE ... WHERE league = '$league'` by string concatenation (now a prepared statement, which also removes one of the DBAL `exec` calls 4.7 listed); `_saveProPlayer` set `draft_id` on the player instead of `pro_player_id`; `TradeRepository` threw `Exception` without the leading backslash, referenced an undefined `$asset->player_id` in an error message and concatenated `errorInfo()` (an array); `new DateTime(null)` and `strlen(null)` for PHP 8; a missing `trade_assets` list in `POST /commish/draft/{id}/trade` is now a 400 "Unable to build trade: Invalid trade data." instead of a PHP warning. *Client:* does not depend on it; the trade screen always sends `trade_assets`.
  - *Kept 1:1 even though it looks wrong:* (1) `PickService::UpdatePick` calls `PickRepository::AddPick` (which also rewrites `pick_time` / `pick_duration` with whatever the loaded pick holds) and reports "Unable to add pick" on failure; (2) ~~`PickHasBeenSelected` has inverted variable names but the right result~~ replaced by `Pick::HasBeenSelected()` in ticket 16; (3) the trade round is the draft's current round, not a client value; (4) a check failure on these routes answers 400 with the response wrapped in an array, not 403/404, like every other check (see 4.1). *Client:* does not depend on (1) to (4).
  - *`TradeAsset` declares `tradeasset_id`.* The entity property now matches the table column, so a loaded asset and a created asset both carry `tradeasset_id` in the JSON. The old entity declared `trade_asset_id`: a loaded asset had `trade_asset_id: null` plus `tradeasset_id`, and a created asset had only `trade_asset_id`. `was_drafted` is still `"1"`/`"0"` (strings) in the create response, because PDO binds it by reference. *Client:* reads neither id field.
  - *`LoadManagerPicks` argument order:* the old trade asset lookup passed the draft where the new `PickRepository::LoadManagerPicks` (fixed in 4.4 to filter by draft) wants a draft id, so `TradeService::GetManagerAssets` now passes both. *Client:* does not depend on it.
  - *Not verified:* the AngularJS commissioner pick entry, trade and pro player autocomplete screens against these endpoints in a browser.
- **4.6 decisions and exceptions.**
  - *Deleting a user is one transaction.* `LoginUserService::DeleteUser` opens it, deletes every draft the user owns through `DraftService::DeleteDraft` (which now joins an open transaction) and then the user; any failure rolls all of it back. The old code deleted draft by draft with no transaction, so a failure part-way left a half-deleted account. `DeleteDraft` also removes the draft's `draft_stats` row now (no foreign keys, so it used to be orphaned). Covered by `AdminTest::testDeleteUserIsAllOrNothing` (a DB trigger forces the second draft delete to fail). *Client:* does not depend on it.
  - *The pro player CSV upload is safer, same format.* The file is parsed completely first, then the league's delete + inserts run in one transaction, so a bad file or a mid-way failure keeps the old player list (the old code deleted first and its `catch (Exception $e)` was missing the leading backslash, so a failure was never caught). New: blank lines are skipped (they used to insert an "Unknown Player"), a UTF-8 byte order mark on the header is ignored, and a CSV with no players is refused with a 400 instead of wiping the league. `SET_CSV_TIMEOUT` still decides whether the time limit is lifted (`hootdraft.set_csv_timeout`). Still 1000 bytes per line, `;` separated, `"Last, First";POS;TEAM`. *Client:* does not depend on it; the admin screen shows the server message.
  - *CSV parsing rules changed.* The name splits on the first comma only, so `Smith Jr, John, III` gives last name `Smith Jr` and first name `John, III` (the old code made any name with more than one comma "Unknown Player"). A name with no comma (`Henry`) is the last name with an empty first name (ticket 09; the old code made it "Unknown Player"). A blank name, or a comma with nothing on one side, refuses the whole file with the row numbers. A cell that is not valid UTF-8 is converted from Windows-1252. A `Player` header is skipped only on the first row; the old code skipped a `Player` row anywhere in the file. *Client:* does not depend on it; the admin screen shows the server message.
  - *League, not sport (ticket 09).* `GET /admin/sports` is now `GET /admin/leagues`, and the `POST /admin/proplayers` form field `sport` is now `league`. The bundled client uses the new names. The draft wire names (`draft_sport`, `sports`, `sport`) did not change. *Client:* depends on it; the bundled client was changed with it.
  - *Admin user update.* The user id comes from the URL only (the old code read `id` from the body, which the client sets to the same value). A missing user is a 404 instead of a 500. The email is lowercased (every lookup lowercases, so a mixed-case address could never log in). New validation: `roles` must be only `ROLE_COMMISH` / `ROLE_ADMIN` ("Role invalid."); the old code stored whatever string arrived. `enabled` is read as a boolean (`"false"` is now false; it used to be true). New validation: a blank name is refused with "Name is missing." (the old code only checked the length), and an Admin cannot remove their own Admin role or disable their own account ("You can't remove your own admin role or disable your own account."), because then nobody can be left to put it back. Roles are parsed by `LoginUser::parseRoles` (ticket 07), so `" ROLE_COMMISH, ROLE_ADMIN,"` is stored as `ROLE_COMMISH,ROLE_ADMIN`. *Client:* the admin edit-user modal shows the server message; it does not depend on these rules.
  - *Stats on add-pick.* `draft_statistics` is calculated after the last pick has committed; if the calculation throws, the pick still succeeds and `draft_statistics` is null (an admin can regenerate with `POST /admin/draft/{id}/stats`). The old code would have failed the whole request. *Client:* does not depend on it; it reads `draft_statistics` only from `/draft/{id}/stats`.
  - *Fixed for PHP 8:* `DraftStatsRepository` read array offsets on `false` for drafts with no picks (now empty strings and zeros), an unknown team or position code falls back to the code itself instead of an undefined offset, and `new DateTime(null)` for a missing start or end time. `POST /admin/draft/{id}/stats` answers 404 for a missing draft (was a 500). *Client:* does not depend on it.
  - *Changed:* regenerating stats now returns 409 unless the draft is complete (an unfinished draft has no end time, so the numbers would be meaningless). The check uses `DraftService::DraftComplete` (ticket 10). *Client:* the admin screen offers regenerate for completed drafts and shows the server message otherwise.
  - *`average_round_seconds` has a new formula (ticket 10, deliberate).* It is the total Pick Duration of the draft divided by the number of rounds, which is what "average round" means. The old code divided the largest one-round total by the number of rounds. Drafts with stats saved by the old code keep the old number until an Admin regenerates them. `DraftStatsCalculationTest` pins the formula. *Client:* the stats page shows the number; it does not depend on the formula.
  - *Not verified:* the AngularJS admin screens and the stats page against these endpoints in a browser, and a real browser CSV upload (the tests post multipart through the kernel).
- **Repository dependencies outside recipe 4c.3.** Recipe 4c.3 says a repository takes `\PDO` and other repositories by class name. `TradeRepository` no longer formats times (`TradeService::GetTrades` does it, and `/draft/{id}/trades` calls the service). `DraftStatsRepository` takes `TransactionService` (ticket 12): it runs its calculation in a transaction, joins one that is already open, and holds the draft row `FOR UPDATE` while it reads. There is no dependency cycle. `DraftRepository` keeps four exceptions:
  - *`CurrentUser`:* the public draft reads (`GetPublicDraft`, `GetPublicDrafts`, `GetPublicDraftsByCommish`) set `commish_editable` and the lock fields for the viewer (`SetSecurityProperties`). Move it together with the status flags if these methods become a separate read model.
  - *`DraftService`:* the status flags. See *Circular dependency* in the 4.1 notes above.
  - *`DatabaseCacheService`:* the Draft cache stays inside the Draft repository. Every write in the repository must reset the cached draft, and a write inside a transaction must reset it again after the commit or rollback (`FlushPendingCacheResets`). If the cache were in the services, each caller would have to repeat these resets, and one missed reset would serve a stale draft.
  - *`ClientTimeFormatter`:* five read methods add " UTC" to the three draft times. The three public ones (`GetPublicDraft`, `GetPublicDrafts`, `GetPublicDraftsByCommish`) also set the status flags and the lock fields, `GetAllCompletedDrafts` also sets the status flags, and `GetAllDraftsByCommish` formats the times only. The cache holds the raw times, and `Load` does not format. If the formatting moved out, each of the five callers would have to format three fields. Move it together with the status flags if these methods become a separate read model.
