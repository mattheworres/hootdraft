# HootDraft: PHP Rewrite

Given that HootDraft's underlying dependencies have been outdated for some time, combined with the fact that software vulnerabilities are being discovered and patched at a rate we have never seen thanks to LLMs - I've decided it's time to try and tackle the bitrot that has naturally set in here.

## Overarching Issues

A rudimentary look over the API code, while not revealing perfection, did reveal that most of the issues aren't necessarily in the code (though I will fix those). The issue is that packages/frameworks like Silex have been deprecated and untouched for many years now.

## Known Compromises

Things decided or sidestepped during step 2. Revisit as noted.

- **Services, repositories and validators were not moved out of `old-api/` in step 2.** Their constructors take the Silex `$app` and look dependencies up by `phpdraft.*` string key, so they can't run under the new kernel until each is converted to constructor injection. That conversion happens per controller in step 4 (the route inventory, `docs/route-inventory.md`, is the checklist). The `RouteCheck` guard infrastructure is in place, but the concrete checks (`draftViewable` etc.) need the ported validators, so they arrive with step 4 too.
- **No `Legacy` autoload mapping.** The old classes keep their original `PhpDraft\...` namespaces, which collide with the new `PhpDraft\` => `src/` mapping, so `old-api/` is read-only reference material, never booted. Port by copying into `src/` and fixing namespaces.
- **Native PDO instead of DBAL for queries.** `doctrine/dbal` 4 removed fetch-into-class, `Statement::fetch()` and `setFetchMode()`, which the ~100 prepared statements in the old repositories rely on. The `PDO` service hands them DBAL's own native connection, so the repositories can be ported mostly as-is. Move to DBAL's `fetchAssociative()`/hydration later if desired (also `fetchColumn` x2 and `exec` x1 need touching).
- **Authentication is a server-side session cookie (step 3).** `hootdraft_session`: HttpOnly, SameSite=Lax, Secure when the request is HTTPS (`cookie_secure: auto`, so behind a TLS-terminating proxy set `framework.trusted_proxies`), valid for a day, stored in `var/sessions` (shared across Deployer releases). `AUTH_KEY`, `AUTH_SECONDS` and `AUTH_KEY_HEADER` are gone with the JWT; everyone is logged out at cutover. Existing users keep their passwords: hashes from the old app verify through Symfony's built-in sha512 x5000 hasher and are rehashed to the modern algorithm (bcrypt/argon, whatever `auto` picks) on that user's next login. Rows still on the old hash are only fully retired once every active user has logged in once.
- **New API surface and a client contract:** `POST /logout` and `GET /me` are new. Every non-GET request must send `X-Requested-With: XMLHttpRequest` (the AngularJS client sets it globally in `requestedWithHeader.config.js`), otherwise 403. The login response no longer contains `token` or `auth_timeout`; the client revalidates its stored login with `/me` at startup and relies on 401s afterwards.
- **Auth behavior changes:** the maximum password length is 72 bytes (was 255; bcrypt ignores the rest, so longer ones are rejected at registration/reset). Completing a password reset also enables the account (the emailed link proves the address, and the old code let unverified users in through reset anyway). The reCAPTCHA check is skipped only when `RECAPTCHA_SECRET` is empty **and** `APP_DEBUG=1`, replacing the old "skip for 127.0.0.1" hack, which never worked behind Docker. Login failures return one generic message for unknown email, wrong password and unverified account.
- **Only the authentication slice of the user code was ported.** `LoginUserRepository`, `LoginUserService` and `LoginUserValidator` in `src/Domain` contain just what login/register/verify/reset need; the rest (profile update, invite, admin user management, public commissioner lookups, `DeleteUser`) comes with its controller in step 4. `CurrentUser` (`src/Security`) replaces `GetCurrentUser()` / `GetUserFromHeaderToken()` for those ports. The email templates were copied to `templates/email/` (the old copies stay in `old-api/` until it is deleted).
- **Not verified in step 3:** the AngularJS client against the new API in a browser (only linted), real SMTP delivery, the real reCAPTCHA call, and Secure-cookie behavior over HTTPS. There is no login throttling yet (`symfony/rate-limiter` is not installed); add it before this faces the internet.
- **Error handler behavior change:** HTTP exceptions keep their status (404, 403, ...) instead of everything becoming 500, and unexpected errors only reveal their message when `APP_DEBUG=1`. The old handler returned the raw exception message with a 500 always.
- **Symfony project root is the repo root** (`config/`, `src/`, `var/`, `bin/` beside the Angular app); only `api/index.php` is a web entry point, and the web server whitelists what is reachable.
- **Settings moved from `appsettings.php` to `.env` / `.env.local`.** The local `appsettings.php`, `phinx.yml` and `deploy.php` are still ignored by git and untouched; regenerate them with `dep setup` (or copy `deploy/deploy.php.release`) for the new formats. `deploy.php` must be rewritten for Deployer 8 (`host()->set('remote_user', ...)`, no `stage()`, no password option).
- **Phinx is now a runtime dependency** (needed on the server to migrate) and the bundled `deploy/composer.phar` and `deploy/phinx.phar` (2019-era) were removed; the server must have `composer` and PHP 8.4+.
- **Vagrant was removed** (Ubuntu 18.04 / PHP 7.2) in favor of the Docker box.
- **Not verified:** a real `dep deploy` against a server, `dep setup`/`package_release` (needs 7-Zip, yarn, gulp), the Apache `.htaccess` and IIS `web.config` rewrites, and the `EXAMPLE_nginx` config. Only the Docker nginx config, the Symfony kernel, tests and Phinx migrations were run. `dep list` and the `deploy` task tree load correctly.
- **4.1 decisions and exceptions.**
  - *Pulled forward from later workstreams:* `DraftDataRepository` (a pure lookup table, listed under 4.6) is needed by every draft read, so it is fully ported; `DepthChartPosition` and `DepthChartPositionRepository::LoadAll` (4.2) are ported because `/draft/{id}?get_draft_data=true` returns the depth chart positions. 4.2 adds the rest of that repository.
  - *Left behind, to be added by the workstream that needs them:* `DraftService` has only the status helpers and `GetCurrentPick` (Create/Update/UpdateStatus/DeleteDraft in 4.3, `GetDraftStats` in 4.6); `DraftValidator::IsDraftStatusValid` waits for `ManagerRepository::DraftHasManagers` (4.2/4.3); the old `draftCompleted` check was not ported because no route uses it; the old `GetAllDraftsByCommish` / `GetAllCompletedDrafts` (admin only) came across with the repository unchanged and are wired up in 4.6. `/draft/{draft_id}/stats` stays unchecked in the inventory. The old `DraftController`, `Entities/Draft` and friends stay in `old-api/` because unported code still reads them; only the old `IndexController` and `CommishController` were deleted.
  - *Circular dependency:* `DraftRepository` needs `DraftService` (status flags) and `DraftService` needs `DraftRepository`. The repository takes the service as a lazy proxy (`#[Autowire(lazy: true)]`). If 4.3 prefers, the status predicates can move to their own small class and the laziness goes away.
  - *Entities stay untyped.* `Draft` keeps untyped public properties plus `#[\AllowDynamicProperties]`: PDO hands back strings or ints depending on the driver, and `ProtectPrivateDraft` deliberately overwrites ints with `''` for locked drafts, so typed properties would break the JSON the client reads.
  - *Behavior kept 1:1 even though it looks wrong:* (1) the `draftSettingUp` check accepts in-progress drafts too (the old closure called `IsDraftSettingUpOrInProgress`); (2) the ten-minute grace period never expires, because the old code computed `end - now` (always negative) and compared it to 600, so a completed draft is always "recent". Fixing both changes what clients can do, so they are your call; each has a comment in code except the second, which is only in the validator. (3) Failed checks answer 400 with the response wrapped in an array, as before, and a missing draft in a check or `/draft/{id}` is still a 500 `{"error": ...}` rather than a 404.
  - *Small fixes for PHP 8 / the new stack:* `new DateTime(null)`, `strlen(null)` and undefined array keys in the validator, a malformed `Exception` constructor call in `NameIsUnique`, `Request::get()` (removed in Symfony 8) replaced by `query`/route arguments, phpfastcache's deprecated `Config` replaced by `ConfigurationOption`.
  - *Cache copies:* `DatabaseCacheService` now stores and returns shallow clones, because phpfastcache hands back the same object it was given within a request, so a locked draft's hidden fields leaked into the next `Load()` in the same process (caught by a test).
  - *Public commissioner JSON:* `LoginUser` gained `verificationKeyCreated` and `creationTime` in step 3, so the public scrub unsets those two as well to keep the response at `id` and `name` only.
  - *Auth plumbing:* `GetUserFromHeaderToken` callers now use `CurrentUser::get()` (the session user), so `commish_editable` and private-draft access follow the cookie session; `IsDraftEditableForUser` takes the `Security\User` (or null) instead of a `LoginUser`.
  - *Draft password header name* is still `X-PhpDraft-DraftPassword` (the `DRAFT_PASSWORD_HEADER` default), since the AngularJS client sends that; rename both together later if wanted.
  - *Not verified:* the AngularJS client against these endpoints in a browser, and the file cache path (`CACHE_PATH=/tmp`) on a real server.
