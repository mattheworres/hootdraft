# HootDraft: PHP Rewrite

Given that HootDraft's underlying dependencies have been outdated for some time, combined with the fact that software vulnerabilities are being discovered and patched at a rate we have never seen thanks to LLMs - I've decided it's time to try and tackle the bitrot that has naturally set in here.

## Overarching Issues

A rudimentary look over the API code, while not revealing perfection, did reveal that most of the issues aren't necessarily in the code (though I will fix those). The issue is that packages/frameworks like Silex have been deprecated and untouched for many years now.

## Known Compromises

Things decided or sidestepped during step 2. Revisit as noted.

- **Native PDO instead of DBAL for queries.** `doctrine/dbal` 4 removed fetch-into-class, `Statement::fetch()` and `setFetchMode()`, which the ~100 prepared statements in the old repositories rely on. The `PDO` service hands them DBAL's own native connection, so the repositories can be ported mostly as-is. **Decided in 4.7: stay on native PDO.** The ~100 prepared statements and `FETCH_CLASS` hydration into the untyped entities work, are covered by the test suite, and DBAL has no equivalent hydration, so a move would be a large diff with no user-visible gain. The three `fetchColumn()` calls are `PDOStatement::fetchColumn()` (not deprecated; only DBAL's own `Statement`/`Connection` lost it) and DBAL already sets `PDO::ERRMODE_EXCEPTION` on the shared handle, so neither needs changing. The one `exec` was removed in 4.5. If this is revisited (for example during the `DraftStatsRepository` tidy), use DBAL directly with a small `Hydrator::into()` helper, not the ORM, one repository at a time.
- **Authentication is a server-side session cookie (step 3).** `hootdraft_session`: HttpOnly, SameSite=Lax, Secure when the request is HTTPS (`cookie_secure: auto`, so behind a TLS-terminating proxy set `framework.trusted_proxies`), valid for a day, stored in `var/sessions` (shared across Deployer releases). `AUTH_KEY`, `AUTH_SECONDS` and `AUTH_KEY_HEADER` are gone with the JWT; everyone is logged out at cutover. Existing users keep their passwords: hashes from the old app verify through Symfony's built-in sha512 x5000 hasher and are rehashed to the modern algorithm (bcrypt/argon, whatever `auto` picks) on that user's next login. Rows still on the old hash are only fully retired once every active user has logged in once.
- **New API surface and a client contract:** `POST /logout` and `GET /me` are new. Every non-GET request must send `X-Requested-With: XMLHttpRequest` (the AngularJS client sets it globally in `requestedWithHeader.config.js`), otherwise 403. The login response no longer contains `token` or `auth_timeout`; the client revalidates its stored login with `/me` at startup and relies on 401s afterwards.
- **Auth behavior changes:** the maximum password length is 72 bytes (was 255; bcrypt ignores the rest, so longer ones are rejected at registration/reset). Completing a password reset also enables the account (the emailed link proves the address, and the old code let unverified users in through reset anyway). The reCAPTCHA check is skipped only when `RECAPTCHA_SECRET` is empty **and** `APP_DEBUG=1`, replacing the old "skip for 127.0.0.1" hack, which never worked behind Docker. Login failures return one generic message for unknown email, wrong password and unverified account.
- **Authentication code layout.** `LoginUserRepository`, `LoginUserService` and `LoginUserValidator` in `src/Domain` started as just what login/register/verify/reset needed; the profile, invite, admin user management, public commissioner lookups and `DeleteUser` were added with their controllers in step 4. `CurrentUser` (`src/Security`) replaces `GetCurrentUser()` / `GetUserFromHeaderToken()`. The email templates live in `templates/email/`. Logging in no longer erases a pending verification / reset key (the old `Login` called `EraseVerificationKey`): a login with the old password must not cancel a reset the owner asked for, and keys expire on their own.
- **Not verified in step 3:** the AngularJS client against the new API in a browser (only linted), real SMTP delivery, the real reCAPTCHA call, and Secure-cookie behavior over HTTPS. There is no login throttling yet (`symfony/rate-limiter` is not installed); add it before this faces the internet.
- **Error handler behavior change:** HTTP exceptions keep their status (404, 403, ...) instead of everything becoming 500, and unexpected errors only reveal their message when `APP_DEBUG=1`. The old handler returned the raw exception message with a 500 always.
- **Symfony project root is the repo root** (`config/`, `src/`, `var/`, `bin/` beside the Angular app); only `api/index.php` is a web entry point, and the web server whitelists what is reachable.
- **Settings moved from `appsettings.php` to `.env` / `.env.local`.** `appsettings.php` is deleted (and no longer git-ignored; `.htaccess` still denies it so a stale copy on an old server can never be served). The local `phinx.yml` and `deploy.php` are still ignored by git and untouched; regenerate them with `dep setup` (or copy `deploy/deploy.php.release`) for the new formats. `deploy.php` must be rewritten for Deployer 8 (`host()->set('remote_user', ...)`, no `stage()`, no password option).
- **Phinx is now a runtime dependency** (needed on the server to migrate) and the bundled `deploy/composer.phar` and `deploy/phinx.phar` (2019-era) were removed; the server must have `composer` and PHP 8.4+.
- **Vagrant was removed** (Ubuntu 18.04 / PHP 7.2) in favor of the Docker box.
- **Not verified:** a real `dep deploy` against a server, `dep setup`/`package_release` (needs 7-Zip, yarn, gulp), the Apache `.htaccess` and IIS `web.config` rewrites, and the `EXAMPLE_nginx` config. Only the Docker nginx config, the Symfony kernel, tests and Phinx migrations were run. `dep list` and the `deploy` task tree load correctly.
- **4.1 decisions and exceptions.**
  - *Pulled forward from later workstreams:* `DraftDataRepository` (a pure lookup table, listed under 4.6) is needed by every draft read, so it is fully ported; `DepthChartPosition` and `DepthChartPositionRepository::LoadAll` (4.2) are ported because `/draft/{id}?get_draft_data=true` returns the depth chart positions. 4.2 adds the rest of that repository.
  - *Left behind, to be added by the workstream that needs them:* `DraftService` has only the status helpers and `GetCurrentPick` (Create/Update/UpdateStatus/DeleteDraft in 4.3, `GetDraftStats` in 4.6); `DraftValidator::IsDraftStatusValid` waits for `ManagerRepository::DraftHasManagers` (4.2/4.3); the old `draftCompleted` check was not ported because no route uses it; the old `GetAllDraftsByCommish` / `GetAllCompletedDrafts` (admin only) came across with the repository unchanged and are wired up in 4.6. `/draft/{draft_id}/stats` stays unchecked in the inventory. The old `DraftController`, `Entities/Draft` and friends stay in `old-api/` because unported code still reads them; only the old `IndexController` and `CommishController` were deleted.
  - *Circular dependency:* `DraftRepository` needs `DraftService` (status flags) and `DraftService` needs `DraftRepository`. The repository takes the service as a lazy proxy (`#[Autowire(lazy: true)]`). If 4.3 prefers, the status predicates can move to their own small class and the laziness goes away.
  - *Entities stay untyped.* `Draft` keeps untyped public properties plus `#[\AllowDynamicProperties]`: PDO hands back strings or ints depending on the driver, and `ProtectPrivateDraft` deliberately overwrites ints with `''` for locked drafts, so typed properties would break the JSON the client reads.
  - *Behavior kept 1:1 even though it looks wrong:* (1) the check formerly named `draftSettingUp` accepts in-progress drafts too (the old closure called `IsDraftSettingUpOrInProgress`); its alias is now `draftSettingUpOrInProgress` so the name says so; (2) ~~the ten-minute grace period never expires~~ fixed: the validator now computes `now - end`, so a completed draft passes `draftInProgressOrCompletedTenMinutes` for ten minutes after it ends and gets a 400 after that (the old code computed `end - now`, always negative, so it never expired); covered in `DraftReadTest`. The first is still your call, with a comment in code. (3) Failed checks answer 400 with the response wrapped in an array, as before, and a missing draft in a check or `/draft/{id}` is still a 500 `{"error": ...}` rather than a 404.
  - *Small fixes for PHP 8 / the new stack:* `new DateTime(null)`, `strlen(null)` and undefined array keys in the validator, a malformed `Exception` constructor call in `NameIsUnique`, `Request::get()` (removed in Symfony 8) replaced by `query`/route arguments, phpfastcache's deprecated `Config` replaced by `ConfigurationOption`.
  - *Cache copies:* `DatabaseCacheService` now stores and returns shallow clones, because phpfastcache hands back the same object it was given within a request, so a locked draft's hidden fields leaked into the next `Load()` in the same process (caught by a test).
  - *Public commissioner JSON:* `LoginUser` gained `verificationKeyCreated` and `creationTime` in step 3, so the public scrub unsets those two as well to keep the response at `id` and `name` only.
  - *Auth plumbing:* `GetUserFromHeaderToken` callers now use `CurrentUser::get()` (the session user), so `commish_editable` and private-draft access follow the cookie session; `IsDraftEditableForUser` takes the `Security\User` (or null) instead of a `LoginUser`.
  - *Draft password header name* is still `X-PhpDraft-DraftPassword` (the `DRAFT_PASSWORD_HEADER` default), since the AngularJS client sends that; rename both together later if wanted.
  - *Not verified:* the AngularJS client against these endpoints in a browser, and the file cache path (`CACHE_PATH=/tmp`) on a real server.
- **4.2 decisions and exceptions.**
  - *Fixed because it could not have run:* `IsManagerValidForCreate` called `NameIsUnique($name)` without the required `$draft_id` (an ArgumentCountError since PHP 7.1, so single-manager create was already broken); it now passes the draft id, so names are unique per draft. Also fixed: an undefined `$draft_id` in the update error message, the `DepthChartPositionRepository::Save` copy-paste that set `round_time_id` (now sets `id`), and null-safe handling of a missing `draft_sport`.
  - *Fixed rather than kept:* `AreManagerIdsValidForOrdering` had `if ($valid = true)` (an assignment, not a check), so a reorder with the wrong number of ids reported the error but still succeeded and the per-id existence checks always ran. It is now `if ($valid)`, so a faulty request fails and skips the per-id queries, as the old comment intended. Create-manager returns the entity without `draft_order` (it is assigned in the DB), as before.
- **4.3 decisions and exceptions.**
  - *Starting a draft and deleting a draft's picks and trades were stubbed here;* both were finished in 4.5 (see below).
  - *Invited users are created enabled.* The client's `/inviteSetup` page uses `/verifyToken` and `/resetPassword`, which refuse disabled accounts since step 3, so a disabled invitee could never set a password. The invitee gets a hash of random bytes nobody knows (cannot log in) and the emailed key proves the address. Because reset keys live for one hour and a verification link for 48, the invite key is dated 47 hours ahead so it stays valid 48 hours; this relies on the single `verificationKeyCreated` column. `LoginUserRepository::Create` now writes `enabled`. The invite and the email are in one transaction, as registration is, and the invitee's address is lowercased.
  - *Profile update:* the password check goes through the configured hasher (legacy digest or modern), a new password is stored with the modern hasher and an empty salt, and the response still carries `invalidateLogin` / `sendEmail`. A changed email or password ends the session on the next request because the user no longer matches the database; a changed email disables the account until the emailed link is followed (a 48-hour verification link). The email goes in the same transaction as the update and errors are logged, with a generic message returned.
  - *Fixed rather than kept:* `GetCurrentPickTimeRemaining` carried on after a repository exception and answered success with an undefined round time; it now returns the failure. `new DateTime(null)`, `strlen(null)` and an `errorInfo()` array concatenation were fixed for PHP 8, and the round time validator casts seconds to int because PHP 8 no longer treats `"q" <= 0` as true.
  - *Request parsing:* the controllers read the JSON body through `getPayload()` instead of `Request::get()`; a malformed `roundTimes` / `depthChartPositions` entry is skipped instead of causing a TypeError.
  - *Not verified:* the AngularJS profile, invite and timer screens against these endpoints in a browser, and real SMTP delivery of the invite and re-verification emails.
- **4.4 decisions and exceptions.**
  - *Search sort is whitelisted.* The old `sort` query parameter was interpolated straight into the `ORDER BY` of three public search queries (SQL injection on an unauthenticated route). `PickSearchModel` now only accepts `ASC` (any case) and falls back to `DESC` otherwise, which is what the client sends.
  - *Pick search is one ranked query.* The strict, loose and split searches are replaced by `PickSearchRepository::Search`: every word must match the first or last name, and the results rank by match quality, then by pick order in the `sort` direction. Details and consequences: `docs/adr/0003`. The `players` full-text index is dropped by migration `20261030000000`.
  - *Fixed rather than kept:* `strlen(null)` on unselected picks (PHP 8.1+ deprecation), `new Exception` without the leading backslash in the repository (it would have thrown a class-not-found error instead of the message), an undefined `$round` in the `LoadRoundPicks` error message, and `PickSearchModel::searchCount()` reading an undefined variable.
  - *Kept 1:1 even though it looks wrong:* (1) the public depth chart `PUT` accepts any `position_id` (it only checks that the pick belongs to the draft) and anyone can call it while the draft is in progress or within ten minutes of ending; (2) `sort_ascending` is a PHP `(bool)` cast, so `sort_ascending=false` is true. The first wants a decision before this faces the internet.
  - *Fixed rather than kept (manager picks):* `PickRepository::LoadManagerPicks` took only a manager id, so `/draft/{open}/manager/{manager from a private draft}/picks/*` and `depth_chart` leaked that draft's picks past `draftViewable`. It now takes the draft id as its second argument and filters on `draft_id` in the query; `PickTest::testManagerRoutesDoNotLeakPicksFromAnotherDraft` covers it.
  - *Not verified:* the AngularJS draft board, search and depth chart screens against these endpoints in a browser. The tests exercise the pick search ranking (see "Pick search is one ranked query" above).

- **4.5 decisions and exceptions.**
  - *Starting a draft now works.* `DraftService::UpdateDraftStatus` runs the old transition (delete trades, delete picks, `SetupPicks`, `SetDraftInProgress`) and `DeleteDraft` also deletes the draft's trades first. Both run in a transaction so a failure part-way no longer leaves a half-started or half-deleted draft (the old code had none). The 4.3 guard ("Starting a draft is not available yet.") is gone.
  - *Trade entry is one transaction.* `TradeService::EnterTrade` swaps the picks, saves the trade and assets and bumps the draft counter together; the old code did four separate writes, so a failure could move picks without recording a trade.
  - *`draft_statistics` is not returned from add-pick yet.* When the last pick completes the draft, the old response also carried `draft_statistics` from `DraftStatsRepository` (4.6). The AngularJS client only reads that field from `/draft/{id}/stats`, so nothing breaks; TODO in `PickService::AddPick`.
  - *Fixed rather than kept:* `ProPlayerRepository::SaveProPlayers` built `DELETE ... WHERE league = '$league'` by string concatenation (now a prepared statement, which also removes one of the DBAL `exec` calls 4.7 listed); `_saveProPlayer` set `draft_id` on the player instead of `pro_player_id`; `TradeRepository` threw `Exception` without the leading backslash, referenced an undefined `$asset->player_id` in an error message and concatenated `errorInfo()` (an array); `new DateTime(null)` and `strlen(null)` for PHP 8; a missing `trade_assets` list in `POST /commish/draft/{id}/trade` is now a 400 "Unable to build trade: Invalid trade data." instead of a PHP warning.
  - *Kept 1:1 even though it looks wrong:* (1) `PickService::UpdatePick` calls `PickRepository::AddPick` (which also rewrites `pick_time` / `pick_duration` with whatever the loaded pick holds) and reports "Unable to add pick" on failure; (2) `PickHasBeenSelected` has inverted variable names but the right result; (3) the trade round is the draft's current round, not a client value; (4) a check failure on these routes answers 400 with the response wrapped in an array, not 403/404, like every other check (see 4.1); (5) `TradeAsset` has `trade_asset_id` but the table column is `tradeasset_id`, so loaded assets carry the latter as a dynamic property and a created asset gets the former.
  - *`LoadManagerPicks` argument order:* the old trade asset lookup passed the draft where the new `PickRepository::LoadManagerPicks` (fixed in 4.4 to filter by draft) wants a draft id, so `TradeService::GetManagerAssets` now passes both.
  - *Not verified:* the AngularJS commissioner pick entry, trade and pro player autocomplete screens against these endpoints in a browser.
- **4.6 decisions and exceptions.**
  - *Deleting a user is one transaction.* `LoginUserService::DeleteUser` opens it, deletes every draft the user owns through `DraftService::DeleteDraft` (which now joins an open transaction) and then the user; any failure rolls all of it back. The old code deleted draft by draft with no transaction, so a failure part-way left a half-deleted account. `DeleteDraft` also removes the draft's `draft_stats` row now (no foreign keys, so it used to be orphaned). Covered by `AdminTest::testDeleteUserIsAllOrNothing` (a DB trigger forces the second draft delete to fail).
  - *The pro player CSV upload is safer, same format.* The file is parsed completely first, then the league's delete + inserts run in one transaction, so a bad file or a mid-way failure keeps the old player list (the old code deleted first and its `catch (Exception $e)` was missing the leading backslash, so a failure was never caught). New: blank lines are skipped (they used to insert an "Unknown Player"), a UTF-8 byte order mark on the header is ignored, and a CSV with no players is refused with a 400 instead of wiping the league. `SET_CSV_TIMEOUT` still decides whether the time limit is lifted (`hootdraft.set_csv_timeout`). Still 1000 bytes per line, `;` separated, `"Last, First";POS;TEAM`.
  - *Admin user update.* The user id comes from the URL only (the old code read `id` from the body, which the client sets to the same value). A missing user is a 404 instead of a 500. The email is lowercased (every lookup lowercases, so a mixed-case address could never log in). New validation: `roles` must be only `ROLE_COMMISH` / `ROLE_ADMIN` ("Role invalid."); the old code stored whatever string arrived. `enabled` is read as a boolean (`"false"` is now false; it used to be true).
  - *Stats on add-pick.* `draft_statistics` is calculated after the last pick has committed; if the calculation throws, the pick still succeeds and `draft_statistics` is null (an admin can regenerate with `POST /admin/draft/{id}/stats`). The old code would have failed the whole request.
  - *Fixed for PHP 8:* `DraftStatsRepository` read array offsets on `false` for drafts with no picks (now empty strings and zeros), an unknown team or position code falls back to the code itself instead of an undefined offset, and `new DateTime(null)` for a missing start or end time. `POST /admin/draft/{id}/stats` answers 404 for a missing draft (was a 500).
  - *Changed:* regenerating stats now returns 409 unless the draft is complete (an unfinished draft has no end time, so the numbers would be meaningless).
  - *Not verified:* the AngularJS admin screens and the stats page against these endpoints in a browser, and a real browser CSV upload (the tests post multipart through the kernel).
